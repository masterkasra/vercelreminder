# API reference

All endpoints are Vercel serverless functions under `/api`. Request and response bodies are JSON.

Authenticated endpoints expect the session token returned by `/api/auth`:

```http
Authorization: Bearer <64-hex-token>
```

An invalid or expired token returns `401 { "error": "..." }`. Error messages are in Persian because they are shown directly in the UI.

---

## `/api/auth`

| Method | Body | Result |
| --- | --- | --- |
| `GET` | – | `{ botUsername }` – used to link to the Telegram bot on the sign-up form |
| `POST` | `{ action: "register", email, password, chatId, firstName?, lastName?, phone?, job?, country? }` | `{ needsVerification: true }` – a 6-digit code is sent to the Telegram chat |
| `POST` | `{ action: "verify", email, code }` | `{ success, user, token }` |
| `POST` | `{ action: "login", email, password }` | `{ success, user, token }`, or `{ needsVerification: true }` for accounts whose chat ID is not verified yet |
| `POST` | `{ action: "forgot", email }` | `{ codeSent, message }` – same response whether or not the account exists |
| `POST` | `{ action: "reset", email, code, newPassword }` | `{ success, user, token }` – all previous sessions are revoked |
| `POST` | `{ action: "logout" }` + bearer token | `{ success }` |

Limits: 10 login attempts / 15 min per email, 10 registrations / hour per IP, 5 codes / hour per email, 5 wrong code entries per code. Codes expire after 10 minutes. Registration is refused with `503` if the server has no `TELEGRAM_BOT_TOKEN`, because chat ownership could not be verified.

## `/api/reminders` 🔒

| Method | Body / query | Result |
| --- | --- | --- |
| `GET` | – | Array of reminders (attachments without file data) |
| `GET` | `?attachment=<id>` | `{ name, type, data }` |
| `POST` | `{ action: "add", id, title, datetime, priority?, tag?, desc?, recurring?, advanceNotice?, subtasks?, attachment? }` | `{ success }` – re-sending the same `id` is ignored (safe for offline retries) |
| `POST` | `{ action: "edit", id, ...same fields }` | `{ success }` – notifications are re-armed only if the time changed |
| `POST` | `{ action: "complete", id, completed? }` | `{ success }` – toggles when `completed` is omitted |
| `POST` | `{ action: "snooze", id, until? , minutes? }` | `{ success }` – `until` is an ISO time computed on the device; falls back to `minutes` (default 60) |
| `POST` | `{ action: "delete", id }` | `{ success }` |

Reminder fields:

| Field | Type | Notes |
| --- | --- | --- |
| `id` | number | Generated by the client (`Date.now()`) |
| `title` | string | Required, ≤ 500 chars |
| `datetime` | ISO string | Due time |
| `priority` | `low` \| `medium` \| `high` | High-priority push notifications stay on screen |
| `tag` | `work` \| `personal` \| `finance` \| `dev` \| `general` | |
| `recurring` | `none` \| `daily` \| `weekly` \| `monthly` | Monthly follows the Jalali calendar |
| `advanceNotice` | number | Days before the due time for an early alert (0–365) |
| `subtasks` | `{ text, done }[]` | ≤ 100 |
| `attachment` | `{ name, type, data }` | `data` is a data URL, ≤ 1 MB file; send `null` to remove |

## `/api/settings` 🔒

| Method | Body | Result |
| --- | --- | --- |
| `GET` | – | `{ dailySummary, summaryHour, tzOffsetMinutes, pushDevices, cronLastRun }` |
| `POST` | `{ dailySummary?, summaryHour?, tzOffsetMinutes? }` | Updated settings |

`tzOffsetMinutes` uses the same sign as JavaScript's `Date#getTimezoneOffset()` (Tehran = `-210`).

## `/api/push`

| Method | Body | Result |
| --- | --- | --- |
| `GET` | – | `{ publicKey }` – VAPID public key for `pushManager.subscribe` |
| `POST` 🔒 | `{ action: "subscribe", subscription }` | `{ success, devices }` |
| `POST` 🔒 | `{ action: "unsubscribe", endpoint }` | `{ success }` |
| `POST` 🔒 | `{ action: "test", delaySeconds? }` | `{ devices, delivered, results: [{ id, service, ok, expired, status, error }] }` |

`results[].id` is the first 12 hex chars of `sha256(endpoint)`, so a device can recognise its own entry without the server echoing push URLs.

## `/api/ai` 🔒

| Method | Body | Result |
| --- | --- | --- |
| `POST` | `{ text, lang, today: { y, m, d } }` | `{ candidates: [{ content: { parts: [{ text }] } }] }` – the text contains a JSON object `{ title, y, m, d, h, min, priority, tag }` |

The prompt is built on the server (the endpoint is not a generic LLM proxy). Limited to 30 requests per hour per account. For `lang: "fa"` dates are in the Jalali calendar.

## `/api/cron`

`GET` – processes due reminders, early alerts, recurrence, Web Push and the morning summary. Call it every minute from an external scheduler. When `CRON_SECRET` is set, send `Authorization: Bearer <secret>` or `?secret=<secret>`.

Response: `{ success, sent, pushes, summaries }`.

On its first run it also re-registers the existing Telegram webhook with a `secret_token` and publishes the bot's command menu.

## `/api/webhook`

`POST` – Telegram updates. After the cron has secured the webhook, requests without the correct `X-Telegram-Bot-Api-Secret-Token` header are rejected.

| Input | Behaviour |
| --- | --- |
| `/start`, `/id` | Replies with the chat ID used for sign-up |
| `/today`, `/list` | Task list with ✅ done and 🗑 delete buttons (delete can be undone for 24 h) |
| `/summary`, `/summary on\|off\|7` | Show or change the morning summary |
| `/help` | Command list |
| `خرید نان فردا ساعت 18:30` | Quick add ("today"/"tomorrow" + time, Persian digits supported) |
| Buttons on a due reminder | Done, snooze 10 min / 1 h / tonight 20:00 / tomorrow 09:00 |
